# 工具页样式体检与修正记录

对首页 + 14 个工具页做了一轮 DOM 级样式体检（不只看截图），
**首轮抓出 58 处问题，修正后归零**。下面是逐项记录。

---

## 一、全局性问题（一改全站受益）

### 1. 辅助文字太淡 —— 对比度仅 2.39:1

`--pk-text-3` 原为 `#98a29c`，在米白底（`#f6f4ef`）上对比度只有 **2.39:1**，
远低于 WCAG AA 要求的 4.5:1。所有结果行的标签、卡片描述、说明文字都用了它，
整体观感就是"字发虚、看不清"。

| | 原值 | 现值 | 对比度 |
| --- | --- | --- | --- |
| 浅色 | `#98a29c` | `#68736d` | 2.39 → **4.48** |
| 深色 | `#6f7873` | `#8a948e` | 3.95 → **5.11** |

### 2. 输入框在白色卡片上"隐形"

`--pk-input` 和 `--pk-card` 原本都是 `#ffffff`，只靠 8% 透明度的 1px 边框分隔 ——
等于没有边界。**这条在压缩后的截图里几乎看不出来，是数值比对才发现的。**

- 浅色 `--pk-input`：`#ffffff` → `#f4f2ec`（比卡片略深的米灰）
- 深色 `--pk-input`：`#22272c` → `#262d32`

### 3. 字号系统性偏小

全站扫了一遍：**8.8px 的色值文字、9.9px 的底部导航标签、10.9px 的表格数字**……

在 390px 宽的屏幕上 `1rpx ≈ 0.52px`，给所有 `font-size` 加了 **22rpx（≈11.4px）下限**，
共调整 **11 个文件、24 处**。

### 4. 触摸目标普遍过小

| 控件 | 原尺寸 | 现尺寸 |
| --- | --- | --- |
| 输入框旁的小动作（示例/清空/读取剪贴板） | 24 × 18px | 约 50 × **30px** |
| 日期推算的快捷标签 | 高 21px | 高 **27px** |
| 结果行复制按钮 | 36 × 26px | 约 50 × **34px** |
| 人民币滑杆（uni-slider 默认） | 高 **18px** | 高 **50px** |
| 还款试算的快捷利率 | 高 23px | 高 **33px** |

低于 28px 的点击区手指基本点不准。

### 5. 复制按钮视觉噪音过大

结果行里约 **62%** 的行都带一个实心青绿色的「复制」，
一屏堆十几个色块，把数据本身压下去了。

改成**素色描边**（透明底 + 细边框 + 次级文字色），并把"复制无意义"的行
（正则页的 `命中数量 0` / `是否匹配 否`）直接关掉复制。

### 6. 卡片内容贴边

`PkCard` 在**没有 title** 时 `padding` 是 0，内容直接顶到卡片边框 ——
输入框左右各只缩进 **1px**，动作按钮压在卡片圆角上。
已给组件加兜底：无标题时四边内边距 24rpx，有标题时只补「左右 + 下」。

### 7. 首张卡片紧贴导航栏

`PkPage` 原本只留了导航栏自身高度，内容区顶部没有任何呼吸位。
已加 **12px**。

## 三、两个值得记住的坑

### 组件 scoped 样式的特异性会跟全局规则打平

scoped 编译后是 `.cls[data-v-xxx]`，**特异性是 0-2-0**（属性选择器按 class 计），
不是 0-1-1。所以在 `App.vue` 里写 `.pk-page .cls`（也是 0-2-0）会打平，
而组件样式排在后面 → **本地的赢**。

实测结果：`.mini-act` 的全局规则生效了（本地没声明 `padding`），
`.quick-i` 和 `.pk-row__copy` 的没生效（本地声明了 `padding`）。

**规矩：本地已声明同属性的，一律改本地规则，别在全局硬碰。**

### 构建会被批量删除保护拦住

`npm run build:h5` 重新构建时要清理 `dist/build/h5/assets`，一次删 53 个文件触发
批量删除保护，**构建直接失败**，而错误信息混在其它输出里很容易漏看。
后果是"以为改好了、体检全绿"，其实测的是上一版产物。

**规避：构建前先 `rm -rf dist`**（`dist` 是纯构建产物，已在 `.gitignore` 里）。
构建后务必确认出现 `Build complete` 再开始验证。
