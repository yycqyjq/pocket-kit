# 打包安卓 App 的完整流程

> 项目已经跑通 `npm run build:app`，产物在 `dist/build/app`。
> 下面两条路线选一条即可，**第一次做强烈建议走路线 A（云打包）**。

---

## 路线 A：HBuilderX 云打包（推荐，最省事）

### 1. 装 HBuilderX

到 https://www.dcloud.io/hbuilderx.html 下载 **App 开发版**（不是标准版，标准版没有打包功能）。

### 2. 导入项目

HBuilderX 菜单 `文件 → 导入 → 从本地目录导入`，选中：

```
/Users/yjq/Desktop/pocket-kit
```

> 不要导入 `dist` 目录，要导入项目根目录。
> HBuilderX 识别到 `src/manifest.json` 后会自动把它当成 uni-app CLI 项目。

### 3. 生成 AppID（必需）

打开 `src/manifest.json`，切到「基础配置」标签：

- **AppID** 现在是空的，点右边的「重新获取」，登录 DCloud 账号后会分配一个
  `__UNI__XXXXXXX` 格式的 ID。
- 应用名称确认为「随身匣」。
- 应用版本名 `1.0.0` / 版本号 `100` 已经填好。

AppID 是云打包的强制项，没有它打不了包。这一步免费，注册 DCloud 账号即可。

### 4. 准备应用图标（必需）

**图标已就位**：`unpackage/res/icons/1024x1024.png` 已放好，各档尺寸也已从它派生，并在
`manifest.json` 的 `app-plus.distribute.icons` 里接好了 Android / iOS 映射；H5 的 favicon 也已配好。
模板自带的 `src/static/logo.png` 占位图（全项目零引用）已删除。以下是「若要从零重做」的准备要求。

准备一张 **1024×1024 的 PNG**（不要透明通道，Android 会按各尺寸自动生成），放到：

```
unpackage/res/icons/1024x1024.png
```

HBuilderX 会自动从它生成 `hdpi / xhdpi / xxhdpi` 等各档图标。

几点要求：

- 正方形、**不透明底**（`sips -g hasAlpha` 应返回 `no`）。图标会被裁成圆角或圆形（各家启动器不同）。
- **图案不要贴边也不要太小。** Android 自适应图标的安全区是画布中央 **61%**（每边留白 19.5%），
  超出这个范围的边缘会被不同厂商的遮罩裁掉；但图案小于 50% 又会在桌面上显得比周围 App 小一圈。
  实用区间是 **图案占画布 52%~61%**。
- 不要预先画好圆角——圆角是系统加的，自己画会出现"圆角套圆角"的锯齿。
- 没有现成图也行：先在 HBuilderX 里填个纯色块占位，把流程跑通，之后再替换，重打包即可。

量图案占比的笨办法（不用装设计软件）：把图丢进任意看图工具目测，或者用纯 Python 解析 PNG
算非背景像素的包围盒。本项目的图标实测为 **51.3% × 50.8%**，居中偏差 <1px——安全，
但已接近下限，若之后重做可以放大到 58%~61% 让它在桌面上更饱满。

### 5. 真机调试（强烈建议先做）

1. 安卓手机打开「开发者选项 → USB 调试」，用数据线连电脑。
2. 首次连接手机会弹出「允许 USB 调试吗」，选允许。
3. HBuilderX 菜单 `运行 → 运行到手机或模拟器 → 运行到 Android App 基座`。
4. 第一次会自动下载安装「HBuilder 标准基座」到手机，之后每次改代码热更新。

真机调试能立刻验证状态栏高度、安全区、震动反馈、深色模式这些浏览器里看不出来的东西。

### 6. 云打包出 APK

菜单 `发行 → 原生App-云打包`：

| 选项 | 建议 |
| --- | --- |
| 平台 | 勾选 Android |
| 打包方式 | 「云端打包」 |
| Android 包名 | 默认是 `com.example.pocketkit`，**请改成自己的**，如 `com.yourname.pocketkit` |
| 证书 | 先用「使用公共测试证书」——只能自己装，不能上架 |
| 广告/统计 | 全部不勾 |

点「打包」，等 3~10 分钟，产物 APK 会出现在 `unpackage/release/apk/` 下，
控制台也会给下载链接。

### 7. 上架应用商店要用的正式签名

公共测试证书不能上架，需要自己生成：

```bash
# 生成 keystore（有效期 25 年）
keytool -genkey -v \
  -keystore pocketkit.keystore \
  -alias pocketkit \
  -keyalg RSA -keysize 2048 -validity 9125
```

`keytool` 来自 JDK，macOS 上装了 JDK 就有。执行后按提示设置密码和证书信息。
然后在云打包界面选「使用自有证书」，上传 `.keystore`、填别名和密码。

> **务必把 keystore 文件和密码存到安全的地方。** 丢失后无法对已上架的应用做版本更新，
> 只能重新上架一个新应用。

## 路线 B：命令行构建 + 离线打包

适合想接 CI 或不想每次开 HBuilderX 的情况。

### 1. 命令行出资源

```bash
cd ~/Desktop/pocket-kit
npm run build:app
```

产物目录：`dist/build/app`。

### 2. 用 HBuilderX 生成可打包资源

菜单 `发行 → 原生App-本地打包 → 生成本地打包App资源`，
选择项目后会在 `unpackage/resources/` 下生成 `__UNI__XXXXXXX` 目录。

### 3. 下载离线打包 SDK

https://nativesupport.dcloud.net.cn/AppDocs/download/android

下载 Android 版 SDK（注意要选与 HBuilderX 版本匹配的，比如 HBuilderX 4.x 对应 SDK 4.x）。

### 4. 用 Android Studio 出包

1. Android Studio 打开 SDK 里的 `HBuilder-Integrate-AS` 工程。
2. 把第 2 步生成的 `__UNI__XXXXXXX` 整个目录复制到
   `app/src/main/assets/apps/` 下。
3. 打开 `app/src/main/assets/data/dcloud_control.xml`，
   把 `appid` 的值改成你的 AppID。
4. 在 `app/build.gradle` 里改 `applicationId` 和签名配置。
5. `Build → Generate Signed Bundle / APK`，选 APK，用你的 keystore 签名。

这条路要装 Android Studio + NDK，第一次配置大概要一两个小时，
除非有特殊需求，否则不值得。

## 关于 Android SDK 版本

`src/manifest.json` 里现在填的是：

```json
"minSdkVersion" : 21,
"targetSdkVersion" : 36
```

- **minSdkVersion 21** = Android 5.0 起可安装。定这么低是因为本项目没有用到任何新 API。
- **targetSdkVersion 36** = Android 16，这是**当前 Google Play 对新应用的硬性要求**
  （2026 年 8 月 31 日起生效，无延期空间）。如果不打算上架、只自己装机，这个值填多少都能装。

> **注意**：36 是 2026 年才普及的目标版本。用**旧版 HBuilderX** 打 36 的包会遇到原生运行时
> 跟不上新系统行为变更的问题（典型症状：网络请求失败、底部出现黑条）。
> **请把用于云打包的 HBuilderX 升到 5.09 及以上**——从 5.09 起云打包环境才使用 compileSdk 36。

### 已知风险：targetSdk 36 下的底部安全区

社区有报告：升到 `targetSdkVersion: 36` 后，部分三星机型（Android 16）底部出现一条黑条，
用 `padding-bottom: calc(24rpx + env(safe-area-inset-bottom))` 的写法在 35 正常、36 异常。

本项目**不受这个具体写法影响**：底部安全区是用 JS 读 `uni.getSystemInfoSync().safeAreaInsets.bottom`
算出来的（见 `src/utils/sys.js`），不依赖 CSS 的 `env()`。
但**这仍然必须在真机上验一次**，因为底部导航栏是该 App 的主界面元素，出问题一眼就能看到。

验证方法：真机装包后看底部导航栏下方是否有多余黑条 / 内容被顶起。
若有异常，先把 `targetSdkVersion` 降回 35 定位，确认真是版本导致再想别的办法。

## 关于权限

`src/manifest.json` 里 Android 只声明了四项权限：

```json
"<uses-permission android:name=\"android.permission.ACCESS_NETWORK_STATE\"/>",
"<uses-permission android:name=\"android.permission.CHANGE_NETWORK_STATE\"/>",
"<uses-permission android:name=\"android.permission.VIBRATE\"/>",
"<uses-permission android:name=\"android.permission.WAKE_LOCK\"/>"
```

因为这个应用完全离线，不需要摄像头、定位、存储、读手机状态。
权限越少，上架审核越快，用户安装时也越放心。

如果你后面加了需要新权限的工具（比如扫码要 `CAMERA`），在
`app-plus.distribute.android.permissions` 数组里按同样格式加一行即可。

## 为什么不做 iOS

（记录一下结论，免得后面重复调研）

- iOS 必须有**付费的苹果开发者账号**（个人/公司 **$99/年**）。免费 Apple ID 只能
  用 Xcode 直连自己的设备装 7 天，**既不能云打包也不能上架**。
- 需要 `.p12` 证书 + `.mobileprovision` 描述文件，且 **Bundle ID 必须与苹果后台
  注册的 App ID 完全一致**，三者错一个就打不出来。
- 安卓有免费的公共测试证书，能直接出可安装的 APK；**iOS 没有对应物**，
  这是两条路线成本差距的根源。
- 真机安装还得预先登记设备 UDID（个人/公司证书上限 100 台），或走 TestFlight。

代码层面其实已经不需要改动就能上 iOS：底部安全区用的是 `safeAreaInsets.bottom`，
应用不申请任何敏感权限所以不用配 `NSxxxUsageDescription`，
纯本地 JS 也不触碰苹果"禁止动态下发可执行代码"的红线。
以后真要上 iOS，只补证书和图标两件事。

## 常见问题

**Q：云打包报错「没有 AppID」**
A：回到第 3 步获取 AppID，`manifest.json` 里的 `appid` 字段不能为空。

**Q：打出来的包打开是白屏**
A：多半是 `manifest.json` 里 `appid` 与实际不匹配，或者用了本地打包但
`dcloud_control.xml` 里的 appid 没改。

**Q：装到手机上图标是 uni-app 的默认图标**
A：没换图标。见第 4 步，放一张 1024×1024 的图到 `unpackage/res/icons/1024x1024.png`。

**Q：图标显示成方角 / 有白边**
A：图标本身必须是**不透明底**；透明底会被垫成白/黑色。另外不要自己在图里画圆角。

**Q：状态栏和内容重叠**
A：项目用的是自定义导航栏，靠 `uni.getSystemInfoSync().statusBarHeight`
顶开。如果换了别的机型有问题，检查 `src/utils/sys.js` 的 `statusBarHeight` 兜底值。

**Q：震动没反应**
A：`manifest.json` 的 `modules` 里已经声明了 `Vibrate` 模块；
另外检查应用设置里「点击震动」开关是否打开。

**Q：Google Play 提示「必须以 Android 16（API 级别 36）或更高级别为目标平台」**
A：见上文「关于 Android SDK 版本」。确认两件事：`manifest.json` 里
`targetSdkVersion` 是 36，以及打包用的 HBuilderX 是 5.09 以上。
注意 HBuilderX 打包面板上的配置可能覆盖 manifest，两边对一下。

**Q：桌面上的图标比别的 App 小一圈**
A：图案占比太低。Android 自适应图标安全区是画布中央 61%，把图案放大到占画布的 58%~61%
即可（本项目当前是 51%，偏小但在安全范围内）。

**Q：图标四角被裁掉了**
A：图案画到了安全区以外。收到中央 61% 范围内重做，或让四周多留白。
