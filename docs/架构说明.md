# 架构说明

## 一、为什么是这个结构

做工具箱 App 最容易踩的坑是「工具越加越乱」：每加一个功能就多一个页面、
多一套导航栏、多一份收藏逻辑。所以这个项目的第一原则是
**让新增工具的成本接近零**。

具体做法：把「工具」从「页面」里剥离出来。

```
pages/tool/tool.vue          ← 唯一的工具容器，只有一个
  └── 根据 URL 参数 id 动态渲染
        └── src/tools/components/ToolXxx.vue   ← 工具本体，只关心内容
```

好处：

- 导航栏、返回按钮、收藏星标、使用记录、页面留白，**只写一次**。
- 新工具不需要碰 `pages.json`、不需要写导航栏、不需要处理返回逻辑，
  只要写一个「一段内容」的 Vue 组件。
- 首页网格、搜索、分类计数、收藏列表、最近使用，全部由
  `src/tools/registry.js` 这一份注册表驱动，天然不会漏。

代价是首包会包含全部工具组件。这些组件都是纯逻辑 + 少量模板，单个通常只有几 KB，
换来的是开发效率，值得。

## 二、分层

```
┌─────────────────────────────────────────────┐
│ pages/            页面与导航，只管编排        │
├─────────────────────────────────────────────┤
│ tools/            工具组件，只管「内容长什么样」│
│                   通过 registry.js 注册       │
├─────────────────────────────────────────────┤
│ components/       通用 UI 原子（卡片/输入/行/分段）│
├─────────────────────────────────────────────┤
│ utils/            纯函数逻辑层，零 UI、零依赖   │
└─────────────────────────────────────────────┘
```

`utils/` 里有两个例外，它们要碰设备，所以单独划出来：`native.js` 是 uni/plus
能力探测与中文降级的唯一出口，`device.js` 是搞机页签的采集层。
新写的工具都守这条线：视图里不出现 `uni.getSystemInfoSync`，更不出现 `plus.android`。
存量还有几处漏网（`device.js` 自己走 `#ifdef APP-PLUS` + `plus.android`、`ToolDevice.vue`
自带一份 probe、`ToolPickcolor.vue` 与 `ToolUseragent.vue` 直接读系统信息），
它们各自都有 try/catch，不算 bug，但属于待收口的重复实现，见第八节。

**关键约束：所有计算都在 `utils/` 里，工具组件里不写公式。**

比如单位换算：`utils/unit.js` 里是数据表 + `convertUnit()` 纯函数，
`ToolUnit.vue` 只负责把它渲染出来。这样做的好处：

- 改公式不用动界面，改界面不会算错数。
- `utils/` 里的函数可以直接在 Node 里跑单测，不需要模拟器。
- 同一个公式能被多个工具复用（比如 `utils/date.js` 同时被时间戳、
  日期推算、使用记录三处使用）。

## 三、主题机制

主题靠 **CSS 变量 + 一个类名**，没有引入任何主题库。

```
src/App.vue
  page { --pk-bg: #f6f4ef; --pk-text: #1d2521; ... }   ← 浅色默认值
  .theme-dark { --pk-bg: #14171a; --pk-text: #e8e6e1; } ← 深色覆盖
```

每个页面最外层挂 `theme-dark` 类，整页换肤：

```vue
<view class="shell" :class="{ 'theme-dark': theme.dark }">
```

`theme` 是一个 `reactive` 单例（`src/utils/theme.js`），
修改时同步写本地存储，App `onLaunch` 时读回来。

**写组件的硬规矩：颜色一律用变量，不许写死十六进制值。**
否则深色模式下必然出现白底白字。目前只有两类例外，都是刻意的：

- 「工具单字块」的 `tint` —— 它在两种主题下都作为大面积色块的底色使用，是品牌色，
  注册表里有一份（首页卡片用），组件里再声明一份同名常量 `TINT` 传给 `PkCard` 的 `accent`。
- 屏幕测试的「考卷」色值 —— 纯色坏点图、灰阶、1px 网格线必须是精确的 RGB，
  跟主题走就没法判读（深色模式把白底染黑，坏点就看不见了）。
  这一组值集中在 `utils/screen.js`，视图里只做拼装；HUD 的字色由 `luma()` 反色算出来，
  保证任何一张考卷上文字都读得清。

导航栏用自定义而非原生（`pages.json` 里 `navigationStyle: "custom"`），
因为原生导航栏在深色模式下同步较慢，会出现一段白条闪烁。

## 四、导航模型

只有两个页面，不是偷懒，是刻意的：

- `pages/index/index.vue` —— 主壳，内含五个页签
  （工具 / 搞机 / 收藏 / 记录 / 设置），用 `v-if` 切换视图而不是 `switchTab`。
  这样切页签不产生页面跳转，没有白屏和闪烁，滚动位置也不会丢。
- `pages/tool/tool.vue` —— 工具详情，`uni.navigateTo` 进入。

两者用 `uni.reLaunch / navigateBack` 通信；返回时靠 `onShow` 钩子刷新
收藏与使用记录。

## 五、数据存储

`utils/storage.js` 是所有持久化的唯一出口，键名统一加了 `pk.` 前缀：

| 键 | 内容 | 说明 |
| --- | --- | --- |
| `pk.theme` | `'light' \| 'dark'` | 主题 |
| `pk.favorites` | `string[]` | 收藏的工具 id，新收藏插到最前 |
| `pk.recent` | `{id, at}[]` | 使用记录，去重、倒序、最多 24 条 |
| `pk.settings` | `object` | 偏好设置 |

所有读写都包在 `try/catch` 里，存储不可用时降级为默认值而不是崩溃。
想做「导出/导入配置」这类功能，只需要在这一层加两个函数。

## 六、跨端兼容上踩过的坑

写这套代码时刻意避开了几类不通用 API：

| 风险点 | 处理方式 |
| --- | --- |
| `btoa` / `atob` 在 App 逻辑层不保证存在 | `utils/base64.js` 手写完整实现，含 UTF-8 与代理对（emoji）处理 |
| `Blob` / `TextEncoder` 跨端不一致 | 自己按码点估算 UTF-8 字节数 |
| `BigInt` 在极老 WebView 缺失 | `utils/radix.js` 用 `HAS_BIGINT` 探测，自动降级为 Number 并提示精度 |
| `crypto.getRandomValues` 不可用 | `utils/random.js` 用「xorshift32 + 时间戳 + 计数器」混合播种 |
| 图标资源需要 png / iconfont | 改用「单字方块」`PkGlyph`，零资源、跟随 tint 变色 |
| 原生 tabBar 图标必需 png 且不能换色 | 改用自绘底部导航，图标是文字，选中态直接改 color |
| 各端 `canvas` API 不统一 | 图片类与二维码/条形码只在 H5/App 的 webview 里画布，用 `#ifdef` 与能力探测分开；其余工具不碰 canvas |
| `uni.*` / `plus.*` 在 H5 预览缺了一半，真机又会因 ROM、模拟器、未授权而局部失败 | 全部收在 `utils/native.js`：先 `typeof` 再 `try/catch`，缺什么用人话写清楚缺什么，一个能力失败只影响它自己那一行 |
| 危险权限没申请时安卓直接抛 `SecurityException` | `utils/native.js` 的 `requestAndroidPermissions()` 统一申请，没有 `plus` 时回 `skipped` 而不是报错；权限常量和中文名也在这同一层 |
| 音频接口各端差异大 | 测试音由 `utils/hardware.js` 现算成 WAV data URL，`playWav()` 先试 uni 播放器再退 webview `Audio`，两条路都没有才报缺失 |

## 七、已知的性能与体积

- 依赖只有 uni-app 官方包 + Vue，**没有引入任何第三方 UI 库或工具库**。
- 三个工具是「输入即计算」的响应式实现（正则、进制、JSON），
  用 `computed` 而不是 `watch + setState`，输入时不会产生额外渲染。
- 批量操作都设了上限（密码 64 位、随机数 500 个、批量校验 500 条、
  还款计划 600 期），避免用户粘贴超长文本时卡死界面。

## 八、下一步可以做什么

按性价比排序：

1. **补一个 `PkPicker` 通用选择器**，把目前在 `ToolUnit` 里内联的 picker 抽出来。
2. **真机自测「安卓原生」这一组**：传感器实验室、硬件测试、屏幕测试、定位与坐标、快捷唤起
   五件已经写完并过了自查，但自查只覆盖降级分支（H5 里连 `plus` 都没有）。
   打真机包要逐个确认：震动真的抖、闪光灯按时亮灭、测试音走扬声器、传感器有实时读数、
   全屏考卷盖得住状态栏与导航栏、定位与唤起弹的是系统框；另外把「拒绝授权」这一分支
   也点一遍——每一处都该留下中文说明，而不是卡住。
3. **分贝计**：唯一还没接的传感器工具，它需要 `RECORD_AUDIO`（第 8 项权限），
   做之前先确认愿意为它多要一项权限；不加的话这组就到此为止。
4. **工具使用频率统计**：`pk.recent` 已经在记录使用时间，
   稍微聚合一下就能做「你最常用的是哪几件」。
5. **配置导出**：`utils/storage.js` 加 `exportAll()` / `importAll()`，
   用 `uni.setClipboardData` 走一遍 JSON 即可。
6. **把重复的原生探测收口到 `native.js`**：`ToolDevice.vue` 里那份 `probe()` 与
   `native.js` 的同名函数几乎一样，`ToolPickcolor.vue` / `ToolUseragent.vue` 直接调
   `uni.getSystemInfoSync()`，`device.js` 自成一套 `#ifdef` 采集。四处合并成一份，
   顺带让 `probe()` 的六个档位成为全站唯一的判定口径。
