## 随身匣（pocket-kit）全项目体检

项目：uni-app + Vue3 离线工具箱，50 个工具，`src/utils/` 是零依赖纯函数层。

**方法**：不启动应用、不用测试框架 —— 用 esbuild 把 `src/utils/*.js` 转译成 CJS，
Node 直接 `require` 跑向量测试 / 往返一致性 / 边界容错。详见 skill `js-toolkit-audit`。

**体检结论**：构建通过、静态一致性（registry ↔ 组件 ↔ utils）全绿、CSS 变量无缺失、
官方测试向量（RFC 4226/6238、MD5/SHA 全家、Luhn、ISO 周）全对。

**发现的问题（已报告，未改，待拍板）**：

P0 —— 结果错误，用户可见
- `date.js` `workdaysBetween`：`Math.min(d, -d)` 恒为负 → 工作日**永远返回 0**。
  调用处 `ToolDateDiff.vue:129-130`（工作日 / 周末两个数字都错）。修法：改 `Math.abs`。
- `sqlfmt.js` `minifySql`：`\s{2,}`→`' '` 压缩**字符串字面量内**的连续空格；
  且 `--` 行注释后换行被换成空格 → 该行 `--` 之后**全部 SQL 变成注释**。语义被改。
- `codefmt.js` `formatHtml(minify)`：未跳过 `RAW_TAGS` → `<pre>` / `<script>` 内容被
  `\s+`→`' '` 压掉，违反 README「pre 内容不会被破坏」的承诺。

P1 —— 明确缺陷
- `codefmt.js` `tokenizeHtml`：用 `indexOf('>')` 找标签结束、不识别引号 →
  属性值含 `>` 时被插入换行（`alt="1 > 2"` → `alt="1 >\n2"`）。
- `cron.js` `describe`：summary 只用 hour/min 拼，忽略 dom/month/dow →
  `0 9 * * 1-5` 汇总成「每天 09:00」，同返回值分项却写「工作日」，自相矛盾。
- `datefmt.js`：单字符占位符 `M/d/H/m/s` 转 strftime 与 Go 全错
  （`yyyy-M-d` → `%Y-M-d`，应为 `%-m` / Go 的 `1`、`2`），moment 恰好正确。
- `manifest.json` `description` 写「共 14 件小工具」→ 实际 50，用户可见。
- 「转 Markdown」功能未实现：`table.js` 的 `toMarkdownTable` 全项目无引用且不产
  Markdown 语法，但 `ToolTable.vue:45` 文案与 README 都声称有此功能。

P2 —— 文档 / 代码卫生
- README 工具表仅 38 条（缺第四批 12 个）；目录树写「14 个工具组件」（实际 50）；
  utils 列表缺 12 个新文件；未链接 `docs/第四批工具说明.md`。
- `storage.js` `readDraft` / `writeDraft` 死代码（无任何调用）。
- 19 个组件 `<style>` 里硬编码语义色（#B4553E / #3F7A6E / #4A6FA5 / #A8642F），
  深色底 #14171A 上 #3F7A6E 对比度约 3:1，低于 WCAG AA。

待商榷：`cny.toChineseUpper(0.5)` 返回「零元伍角」（票据规范宜作「伍角」）；
`sortLines` 只有字典序（'10' < '9'）；`initials('重庆')` 取不到多音字（得 ZQ）。

## 第三轮：修复（授权范围 = P0 全部 + P1 全部）

二夜明确授权后动手。改动文件：
`src/utils/{date,sqlfmt,codefmt,cron,datefmt,wordfreq,table}.js`、
`src/tools/components/{ToolTable,ToolDatefmt}.vue`、`src/manifest.json`、`README.md`。

**P0-2 的修法是架构性的**：不修正则，而是给 `formatSql` 加 `oneLine: true` 模式，
压平走 token 流而不是对已格式化的文本做正则替换。正则压平必然踩字符串字面量与行注释，
治不了根。

**P1-3（datefmt）比报告里写的深三层** —— 这是本轮最大的发现：
1. **缺 token**：`render` 产出 `M/d/D/DDD/002` 但 `tokens` 没有 → 译回来当字面量。
   写了个「render→parse 往返矩阵」探针，一次抓出 **9 处**（java 3、moment 3、go 3）。
2. **顺序依赖**：`parsePattern` 靠手写数组顺序做「长 token 优先」。
   补进单字符 `1` 后 Go 的 `15` 会被拆成 `1`+`5` → 改成**按长度降序匹配**，机制上免疫。
3. **补零语义**：Java `H:m:s` 实际输出 `14:5:9`，但 `renderSample` 一律补零 → 示例值错。
   新增 `hour24n/hour12n/minuten/secondn/dayOfYearn` 五个「不补零」类型，
   并在 `convert` 里做**双向兜底**（缺变体时退回另一变体，而不是让字段变空串）。
   `%-H/%-I/%-M/%-S` 先在本机 C 库实测可用才敢用。

**我自己引入又修掉的回归**：新增内部类型后，`ToolDatefmt.vue` 的 `TYPE_CN` 缺这些 key，
字段对应表会显示裸的 `hour24n`。→ 教训：**引入新内部枚举值后，必须 grep 所有 UI 标签映射表**。

**顺带修的 P2**：`cron.js` `nextRuns` 的 JSDoc 写 `Array<{date,text,relative}>`，
实际返回 `Date[]`（`ToolCron.vue` 也按 Date 用）→ 文档对齐代码。
另 README 目录树「14 个工具组件」→ 50（与 manifest 同一类过期文案）。

**未修，等拍板**：

- `workdaysBetween` 的**半开区间**口径：9/1→9/30 = 21 工作日 + 8 休息日 = 29，
  但「9月1日到9月30日」显示 29 天可能与直觉不符。改口径是行为变更。
- `docs/样式修正记录.md` 的「14 个工具页」是历史记录，保留

**验证（全绿）**：纯函数 110 断言 / 往返矩阵 0 缺陷 / 浏览器实测 34 断言 / 50 工具冒烟 50-50。

**两个新踩的坑**：

## 第五轮：三件待拍板事项（授权「按你的方案都改」）

**先确认再动手**：这轮一开始先读代码确认口径，不凭印象改。三件都做完了。

**① 占位符对比度 2.35 → 5.03（浅色）/ 3.07 → 4.75（深色）**

根因不是「颜色选得浅」，而是 **`App.vue` 里 `.pk-ph` 硬编码了 `#98a29c`**。
这个值原本等于旧版 `--pk-text-3`，后来 `--pk-text-3` 为过对比度检查被加深到 `#68736d`，
硬编码那份没跟着走 —— 变量化了，却留了副本。而且占位符底色是 `--pk-input`（`#f4f2ec`），
比卡片白底更深，更吃亏。

改法：新增独立变量 `--pk-ph`（浅 `#5f6a64` / 深 `#8f9993`），
删掉 `.theme-dark .pk-ph` 那条硬编码覆盖。

**教训（值得写进 skill）**：主题变量化改造要**连带清掉所有硬编码副本**。
只改变量、不改硬编码，表面「已主题化」，实际留了一处会随变量漂移而静默劣化的死角。

**② 工作日口径：半开 → 含首尾（两种都保留，不二选一）**

- `date.js` `workdaysBetween` 加 `opt.inclusive`：默认 `false` 维持半开 `[a,b)`；
  `true` 走闭区间 `[a,b]`。
- `ToolDateDiff.vue` 改 span/gap 双口径：**共几天（含首尾）**为主，
  **相隔天数（不含结束日）**单列一行；工作日/休息日改按含首尾算。

关键收益是**恒等式**：改前「29 = 21 + 8」三个数字单看都对、凑一起不像在说同一件事；
改后「工作日 + 休息日 = 共几天」用户可以自己验算（30 = 22 + 8，365 = 261 + 104）。

**③ 删 `datefmt.js` 顶部 `const T`**（22 项字段类型中文标签表，全项目零引用，
真正干活的是 `ToolDatefmt.vue` 的 `TYPE_CN`）。留着是陷阱：看着像权威映射表，改类型时容易被误改。

**踩到的坑（新）**：
- **`build:app` 的产物不会随 `build:h5` 一起更新**。第一轮跑过 `build:app`，第二轮只改源码没重跑，
  `dist/build/app/app.css` 里仍留着旧的 `#98a29c`。→ 验证产物必须**两端分别重跑、分别核验**，
  不能拿 H5 的干净产物推断 App 端也是干净的。（用 `node` 读产物 CSS 提取 `.pk-ph` 规则核验。）
- **改了行为就必须同步改断言**。第一轮 `ui-fixes.mjs` 有 4 项断言写死了旧标签
  （`工作日（周一至周五）`）和旧口径（21 天），改口径后它们失败 —— 这是**断言过期**不是回归。
  不改的话，下次跑测试就无法区分「真回归」和「断言过期」。

**验证（全绿）**：纯函数 110 + 10（新 `t13` 口径/恒等式/暴力对账）、往返矩阵 0 缺陷、
浏览器 38 断言（原 34 + 新 4）、占位符 6/6 组合 ≥4.5:1（新 `t12`，102 次页面加载）、
`datediff` UI 23 断言（新 `t14`，4 场景）、50 工具冒烟 50/50、README 对撞 13/13、
`build:h5` + `build:app` 均通过且产物 CSS 已核验。
